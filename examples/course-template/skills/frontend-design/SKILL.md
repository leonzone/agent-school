# 前端设计

## 必要输入

- 确认页面目标、用户任务、内容优先级和主要使用场景。
- 确认现有项目技术栈、设计规范、组件约定及可修改范围。
- 确认目标设备、浏览器、响应式要求和可访问性要求。
- 获取真实文案、数据状态和素材；缺失时使用明确示例并标注。

## 执行流程

1. 阅读现有页面和组件，复用项目已有模式与设计变量。
2. 梳理信息层级、主要操作及加载、空白、错误和成功状态。
3. 先形成页面结构与交互方案，再确定布局、间距和视觉层级。
4. 设计移动端到桌面端的适配方式，避免仅按单一尺寸布局。
5. 在既定技术栈内实现语义化结构和清晰的键盘交互。
6. 为控件提供可理解名称，保证焦点可见、对比度合理。
7. 检查长文本、空数据、错误数据和不同视口下的表现。
8. 运行项目已有检查，并说明实际验证范围与未覆盖事项。

## 输出结构

1. **设计说明**：用户任务、信息层级和关键设计取舍。
2. **页面实现**：符合项目结构的组件、样式与必要状态。
3. **交互状态**：加载、空白、错误、成功及响应式行为。
4. **验证结果**：执行的检查、测试视口和发现的问题。
5. **待确认项**：缺失素材、内容假设和后续设计建议。

## 边界

- 不擅自更换技术栈、引入依赖或修改无关模块。
- 不用视觉稿描述冒充已实现页面，不声称未运行的测试已通过。
- 不以悬停或颜色作为唯一交互提示，不忽略键盘操作。
- 不编造真实业务数据、品牌授权或用户研究结果。

## 交付检查

1. 对照需求检查主要任务、内容层级和全部界面状态。
2. 检查不同视口、键盘焦点、语义标签和文本溢出。
3. 确认改动范围最小，并如实记录构建与测试结果。
