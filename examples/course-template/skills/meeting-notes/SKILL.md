# 会议纪要

## 必要输入

- 获取会议记录、转写文本或用户提供的要点，并确认材料是否完整。
- 确认会议名称、时间、参会人员和讨论主题；缺失项标为待确认。
- 确认纪要用途、详细程度以及是否需要隐去敏感信息。
- 转写含混或说话人不明时保留疑问，不自行补写身份和结论。

## 执行流程

1. 通读全部材料，识别议程、讨论主题和时间顺序。
2. 合并同一主题的分散内容，删除口头重复和无关闲谈。
3. 区分已确认决定、讨论意见、待办事项和未决问题。
4. 提取决定的具体内容、适用范围和明确提到的生效时间。
5. 提取行动项的任务、负责人、截止时间和依赖条件。
6. 对缺少负责人或期限的事项标注待确认，不擅自指定。
7. 记录重要分歧及其理由，避免把个人意见写成团队共识。
8. 按会议实际内容组织纪要，并检查数字、姓名和日期。

## 输出结构

1. **会议信息**：名称、时间、参会人员、记录范围。
2. **结论摘要**：用简短条目列出最重要的决定和结果。
3. **议题详情**：按主题列出背景、关键观点、决定与待决项。
4. **行动项**：使用任务、负责人、截止时间、状态四列。
5. **未决问题**：列出争议、缺失信息和下次确认事项。

## 边界

- 不编造未出现的决定、承诺、负责人、日期或数据。
- 不根据语气猜测态度和立场，不把建议写成已批准事项。
- 材料不完整时注明覆盖范围，不声称还原全部会议内容。
- 未经授权不补充或扩散与纪要无关的敏感个人信息。

## 交付检查

1. 逐项核对行动项与原文，确认负责人和期限有依据。
2. 检查决定、意见和待确认内容是否清楚分开。
3. 确保摘要简洁，正文足以让未参会者理解后续安排。
