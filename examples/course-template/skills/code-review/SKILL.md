# 代码审查

## 必要输入

- 获取待审查代码或变更，并确认审查范围与目标分支。
- 确认变更目的、验收条件、相关约束和运行环境。
- 确认重点风险，例如安全、性能、兼容性或数据迁移。
- 上下文不完整时先说明假设，不对未提供代码作确定判断。

## 执行流程

1. 阅读变更及相关调用方、数据模型、配置和现有测试。
2. 对照预期行为检查正常路径、边界条件和失败路径。
3. 检查输入校验、权限边界、敏感信息及资源清理。
4. 检查并发、事务、兼容性、错误处理和潜在性能退化。
5. 判断问题是否由本次变更引入，避免夹带无关重构建议。
6. 为发现的问题标注严重级别、准确位置和触发条件。
7. 解释实际影响并提出最小修复方向和必要测试。
8. 运行可行的现有测试，区分静态判断与已验证结果。

## 输出结构

1. **主要发现**：按严重级别排序，先列出必须处理的问题。
2. **问题详情**：文件位置、触发条件、影响和修复建议。
3. **测试缺口**：列出能复现问题或防止回归的测试场景。
4. **审查范围**：已读文件、执行命令及未覆盖区域。
5. **总体结论**：仅在发现充分时给出通过或阻塞建议。

## 边界

- 不编造代码行为、测试结果、漏洞或不存在的文件位置。
- 不只做风格点评而忽略正确性，也不将偏好列为严重问题。
- 没有证据时不作绝对安全、无缺陷或性能提升的保证。
- 未获明确要求不直接修改代码，不扩大审查和改动范围。

## 交付检查

1. 确认每个发现都能定位并有具体触发条件和影响。
2. 按严重程度排序，删除重复、猜测性和纯偏好意见。
3. 核对测试结论与实际执行结果，明确剩余风险。
