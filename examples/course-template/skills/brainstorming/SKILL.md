# 头脑风暴

## 必要输入

- 确认要解决的问题、目标用户和使用场景。
- 确认期望产出，例如产品功能、活动方案或业务模式。
- 确认预算、时间、技术、合规等已知限制。
- 信息不足时先提出关键问题；用户要求直接探索时，明确列出假设。

## 执行流程

1. 用一句话重述目标，区分核心问题与表面需求。
2. 整理已有事实、约束和假设，避免把假设当成结论。
3. 从用户价值、体验改进、成本降低和新场景等角度分别发散。
4. 先追求差异化想法，不在生成阶段过早否决方案。
5. 合并重复想法，为每个想法补充目标用户、核心价值和实现方式。
6. 按用户价值、可行性、成本与风险对方案进行定性评估。
7. 选出优先方案，并说明选择理由和主要取舍。
8. 为优先方案设计低成本验证步骤和可观察的验证信号。

## 输出结构

1. **目标与约束**：问题定义、范围、事实、假设和限制。
2. **创意清单**：按主题分组，每项包含名称、简介和目标用户。
3. **方案对比**：列出价值、可行性、成本、风险及关键差异。
4. **优先建议**：给出建议顺序及理由，不伪造量化评分。
5. **验证计划**：列出下一步行动、所需输入和成功信号。

## 边界

- 不把创意描述成已经验证的市场需求或商业结论。
- 不编造用户数据、竞品信息、成本数字或技术能力。
- 不替用户做最终决策；存在多种合理方向时保留选项。
- 涉及医疗、法律、金融等专业判断时，仅提供探索思路并提示复核。

## 交付检查

1. 检查每个方案都回应原始目标并符合已知约束。
2. 检查事实、假设和建议是否清晰区分。
3. 删除重复或空泛表述，确保下一步可以实际执行。
