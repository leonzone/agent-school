# 演示文稿

## 必要输入

- 确认演示主题、目标听众、使用场合和期望促成的行动。
- 确认演讲时长、页数范围、语言、风格和既有品牌要求。
- 获取必要素材、数据、图表、参考文档及必须保留的内容。
- 信息不足时先确认核心叙事；无法确认视觉要求时采用简洁版式。

## 执行流程

1. 确定一句核心主张，并按听众背景安排信息和详略。
2. 设计开场、问题、证据、方案和行动的叙事顺序。
3. 制定逐页大纲，让每页只承担一个明确的信息任务。
4. 为每页撰写结论式标题、少量要点和必要的口头说明。
5. 根据内容选择图示、表格或图表，优先表达关系而非装饰。
6. 统一术语、字体层级、配色、对齐和数字单位。
7. 检查页面间过渡，删除重复内容并控制单页信息密度。
8. 根据当前工具能力交付文稿大纲或直接生成演示内容。

## 输出结构

1. **演示定位**：听众、目标、时长、核心主张和叙事线。
2. **逐页内容**：页码、标题、正文要点、视觉建议和讲稿提示。
3. **关键图表**：说明数据、图表类型、标注和来源。
4. **结尾行动**：总结决定、建议或听众下一步。
5. **制作备注**：列出缺失素材、待核实数据和版式要求。

## 边界

- 不编造数据、图表、客户案例、引语或视觉素材来源。
- 无法生成特定文件格式时，不以文本大纲冒充已生成文件。
- 不声称未实际渲染检查过的页面不存在溢出或错位。
- 未经授权不使用受限品牌素材，不泄露输入中的敏感信息。

## 交付检查

1. 检查页数与时长是否匹配，每页是否只有一个中心信息。
2. 核对标题、正文、图表和讲稿中的数字及结论一致性。
3. 检查开场是否建立背景，结尾是否明确行动。
